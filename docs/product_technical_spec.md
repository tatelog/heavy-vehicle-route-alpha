# 大型車両ルート確認アプリ 仕様書

この文書は、既存の試作実装を別環境・別UIで再実装できるように、構想、機能要件、技術スタック、外部サービス、データ構造、判定ロジックを整理したものです。  
画面デザインは固定しない。UIは再生成・再設計してよい。ただし、業務フローと安全上の制約は維持する。

## 1. 目的

建設・搬入現場などで、大型車両、中型車両、特殊車両が目的地まで安全に進入できる可能性を事前確認するための補助アプリを作る。

主な目的は次の通り。

- 現在地または指定した出発地点から、目的地までの候補ルートを表示する。
- 車両区分や車両サイズに応じて、通行可否の参考判定を行う。
- 大型車で問題になりやすい曲がり角、狭隘区間、通行不可に近い区間を確認しやすくする。
- 運転中は余計な操作を減らし、直近指示と現在地追従を優先する。
- 将来的に交通情報、低速検知、現場共有、チーム位置共有に拡張できる構成にする。

## 2. 想定ユーザー

- 建設現場の監督、職長、配車担当
- 大型車両、ユニック車、ミキサー車、トレーラー、クレーン車などの運転手
- 搬入経路を事前に説明・共有する人
- ITに詳しくない高齢ユーザーを含む

UIは専門用語を避け、操作は「車両を選ぶ」「行き先を入れる」「候補を確認する」「案内を始める」の順にする。

## 3. 実装方針

### 3.1 UI自由度

UIはこの仕様書に縛らず、再設計してよい。

維持すべきものは次の操作フロー。

1. 車両選択
2. 現在地取得または出発地点指定
3. 行き先検索
4. 行き先候補確認
5. ルート候補選択
6. ルート確定
7. 運転時案内

画面は最低限、次の3系統に分ける。

- ルート選定
- 運転時
- 管理画面

ハンバーガーメニュー、タブ、ボトムナビなどの表現は自由。

### 3.2 安全上の原則

- 本アプリは正式な通行許可・通行可否を保証しない。
- 正式な確認は国の特殊車両通行確認システム等で行う。
- 運転中は、ルート以外の道路をタップして通行可否を調べる機能を出さない。
- 運転中は、直近指示、現在地、再検索、必要最低限の共有操作に絞る。
- 曲がり角判定は「参考」。現地確認、誘導員判断、道路状況を優先する。

## 4. 技術スタック

### 4.1 現行試作

- HTML単体アプリ
- CSS
- Vanilla JavaScript
- Leaflet
- 国土地理院タイル
- OpenStreetMapタイル fallback
- OSRM公開ルーティングAPI
- Nominatim検索
- Web Geolocation API
- Web Speech API
- PWA manifest
- Service Worker
- PocketBase想定の共有データ構造

### 4.2 再実装時の推奨構成

UIを作り直す場合は、次の構成が扱いやすい。

- フロントエンド: React / Vue / Svelte / Solid のいずれか
- 地図: Leaflet または MapLibre GL JS
- 状態管理: フレームワーク標準のstate、または軽量store
- ルーティング: OSRM、GraphHopper、Valhalla、自前OSMグラフのいずれか
- 位置情報: Web Geolocation API
- 音声案内: Web Speech API
- PWA: Web App Manifest + Service Worker
- 共有・ログ: PocketBase、Supabase、Firebase、または自前API

初期版は静的配信でよい。GitHub Pagesでも動作可能。ただしGPSはHTTPS配信が必要。

## 5. 外部サービス・データ

### 5.1 地図

必須:

- 国土地理院タイル

任意:

- OpenStreetMapタイル
- MapLibre用ベクトルタイル

注意:

- 地図背景は情報量が多くなりやすいため、彩度・コントラストを抑える。
- 道路判定の線と背景地図の線が混同しないようにする。

### 5.2 住所・施設検索

現行試作:

- Nominatim

要件:

- 入力した行き先に対して複数候補を出す。
- 候補を選んだ時点で即ルート検索に進めない。
- 地図上で行き先ピンを確認し、「この行き先でよいか」を確定してからルート候補へ進む。
- 検索精度が低い場合は、住所や施設名を詳しく入れるよう促す。

### 5.3 ルート検索

現行試作:

- OSRM公開API

要件:

- 複数候補を出す。
- 通行不可判定に近い候補は、原則候補から除外する。
- 高速道路ON/OFFの選択を持つ。
- 現行OSRM公開APIでは高速道路の完全除外はできないため、OFF時は高速を含む候補の優先度を下げる。
- 将来、自前グラフまたは対応ルーティングAPIに移行すれば完全除外できる。

### 5.4 通行可能道路データ

現行試作:

- OSM由来の道路中心線
- 仮の道路属性
- 重要物流道路、緊急輸送道路、一般道の分類

必要な属性:

- 道路種別
- 幅員目安
- 高さ制限目安
- 重量制限目安
- 通行可否判定用の分類
- データ出典
- 更新時刻

正式運用では、公的データまたは許諾済みデータを使う。

### 5.5 交通情報

フェーズ2以降。

候補:

- JARTIC系データ
- 国土交通省系データ
- NEXCO等の公開情報
- 自社共有マーカー

要件:

- 無償利用可能な範囲を優先する。
- 利用規約、出典表示、保存可否、再配布可否を確認する。
- 交通情報APIが未接続でも、GPS・ルート候補・音声案内・通行可否参考は動作する。

## 6. 車両仕様

### 6.1 基本区分

初期選択は次の3つを基本とする。

- 中型
- 大型
- 特殊

普通車は不要。

### 6.2 その他車両

「その他」を選ぶと詳細車両を選べる。

候補:

- ユニック
- ミキサー
- ラフタークレーン
- 低床トレーラー
- 高床トレーラー
- セミトレーラー
- カスタム入力

ただし車種は無限に増えるため、最終的には「幅・高さ・重量・長さ・最小回転半径・軸数」などの数値で扱う。

### 6.3 必要な車両属性

最低限:

- 全幅
- 全高
- 総重量

曲がり角確認まで行う場合:

- 車長
- ホイールベース
- 最小回転半径
- 後輪軌跡
- 内輪差
- オーバーハング

## 7. 主要機能

### 7.1 車両選択

初回起動時に車両選択を促す。  
選択結果は端末に保存する。

再選択は管理画面から行う。

### 7.2 現在地取得

要件:

- GPSで現在地を取得する。
- 取得失敗時は理由を表示する。
- 権限拒否、HTTPSでない、端末が位置を特定できない、などを区別する。
- 取得済み現在地がある場合、右下の現在地アイコンで地図を戻す。
- 位置情報は継続更新する。

注意:

- `file://` ではGPSが使えない場合がある。
- GitHub PagesなどHTTPS環境で確認する。

### 7.3 出発地点

原則はGPS現在地を使う。

ただし、次の場合は手動指定できる。

- GPSが使えない
- 事前に別地点を出発地点として検討したい
- 現場集合地を起点にしたい

出発地点は勝手に書き換えない。  
GPS更新で「現在地」は動いてよいが、「手動指定した出発地点」は固定する。

### 7.4 行き先検索

要件:

- 行き先名、住所、座標を入力できる。
- 複数候補を表示する。
- 候補を押すと地図上にピンを出す。
- 「この行き先でよいか」を確認してからルート候補へ進む。

禁止:

- 検索結果の先頭候補を自動確定しない。
- 行き先選択を飛ばしてルート選択へ進まない。

### 7.5 ルート候補

要件:

- 複数候補を表示する。
- 距離、所要時間、通行可能道路との整合状況を表示する。
- 高速道路を含むかどうかを表示する。
- 候補を選ぶと地図上で確認できる。
- 確定するまで運転案内を開始しない。

フロー:

```text
行き先選択
↓
ルート選択
↓
案内開始
```

この順序は必ず守る。

### 7.6 通行可否の参考判定

判定は車両属性と道路属性を比較する。

例:

- 車幅 > 道路幅目安: 通行不可または要確認
- 車高 > 高さ制限: 通行不可
- 重量 > 重量制限: 通行不可

ルート候補に通行不可区間が含まれる場合、原則候補から除外する。

表示方針:

- 通れる可能性が高い区間
- データがなく照合できない区間
- 選択車両では厳しい区間

ただし、色や線種はUI側で自由に設計してよい。  
凡例と実際の地図表示は必ず一致させる。

### 7.7 曲がり角確認

大型車では、道路幅だけでなく曲がり切れるかが重要。

要件:

- ルート案内の曲がり角に「曲がり確認」ボタンを出す。
- 選択車両の軌跡を地図上に重ねる。
- 背景地図なしの図だけでは判断できないため、必ず地図上に重ねる。
- 赤丸などで曲がり始点を表示する。
- 始点は道路中心ではなく、曲がり始める地点に合わせる。
- 左折・右折で車両向きと軌跡を切り替える。
- 回転・移動できる。
- 判定ポップは右上の閉じるボタンで消せる。

判定表示:

- 曲がれる見込み
- 要確認
- 厳しい可能性
- 道路幅データ不足

これは参考であり、現地確認を優先する。

### 7.8 運転時画面

運転時は情報を減らす。

表示するもの:

- 直近指示
- 次の曲がり地点
- 案内開始 / 停止
- ルート再検索
- 曲がり確認

表示しないもの:

- ルート外道路の通行可否タップ判定
- 現場共有の未実装ボタン
- 不要な設定説明
- デバッグ的な件数表示

### 7.9 音声案内

Web Speech APIを使う。

案内タイミング:

- 曲がり地点の300m以内
- 次の曲がりまで3km以上ある場合は1km前
- 交差点名が取れる場合は読み上げる

音声ON/OFFは管理画面に置く。  
運転時画面には音声ON/OFFボタンを置かない。

### 7.10 共有

フェーズ1:

- 共有リンク作成
- LINE共有
- LINEビジネス等に転記しやすい文章コピー

フェーズ2以降:

- チーム位置共有
- 共有マーカー
- 低速移動検知
- 渋滞・通行止め・工事・狭い地点の共有

運転時に常時共有ボタンを並べるのは避ける。  
想定速度より遅い状態が一定時間続いたときに、必要ならポップで登録を促す。

### 7.11 PWA

要件:

- ホーム画面に追加できる。
- 管理画面に「ホーム画面に追加」導線を置く。
- iPhoneでは共有ボタンから追加する案内を出す。
- Android/Chromeでは `beforeinstallprompt` に対応する。

必要ファイル:

- `manifest.webmanifest`
- `sw.js`
- アイコン 192px / 512px

## 9. 画面仕様

UIは自由に再設計してよい。  
ただし、以下の情報設計は維持する。

### 9.1 初回車両選択

目的:

- 先に車両区分を決める
- その後GPS取得へ進む

選択肢:

- 中型
- 大型
- 特殊
- その他

### 9.2 ルート選定

含めるもの:

- 行き先入力
- 出発地点表示
- 地図で出発地点を選択
- 高速道路ON/OFF
- 共有
- 行き先候補
- ルート候補
- ルート確定

### 9.3 運転時

含めるもの:

- 直近指示
- 案内開始
- ルート再検索
- 曲がり確認

含めないもの:

- 管理設定
- 共有マーカー投稿
- 通行可否の自由タップ

### 9.4 管理画面

含めるもの:

- 車両条件変更
- 表示テーマ
- 音声案内ON/OFF
- 縮尺表示ON/OFF
- ホーム画面に追加
- 表示レイヤ
- 注意書き、出典

## 10. 共有リンク

共有リンクには最低限次を含める。

- 行き先
- 出発地点座標
- 車両区分
- 必要ならルームID

例:

```text
?dest=富山県庁&vclass=large&lat=36.701500&lng=137.214000
```

## 11. エラー表示

GPS:

- 権限拒否
- HTTPSでない
- 端末が位置を特定できない
- タイムアウト

検索:

- 候補なし
- 精度不足
- 通信失敗

ルート:

- ルートなし
- 通行可能候補なし
- 通信失敗
- 高速道路OFFでも完全回避できない可能性

エラーはユーザーが次に何をすればよいかまで表示する。

## 13. 実装時の注意

- GPS現在地と手動出発地点を混同しない。
- 行き先候補を自動確定しない。
- ルート候補を選んだだけで案内を始めない。
- ルート確定前に音声案内を開始しない。
- 運転中に余計な地図タップ判定を出さない。
- 凡例と地図上の線色・線種を一致させる。
- 曲がり角の左折・右折で車両向きと軌跡を一致させる。
- `0,0` 座標を有効な出発地点として扱わない。
- GitHub Pages等のHTTPSでGPSとPWAを確認する。

## 14. 非エンジニア向け説明文

現在地と行き先を入れると、大型車が通れそうな道を地図上に表示します。国土地理院の地図を使い、曲がり角や道幅の確認、音声案内にも対応した試作版です。
